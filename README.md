# ระบบติดตามงานฝ่าย — คู่มือติดตั้ง

ระบบมี 2 ไฟล์ คือ `Code.gs` (หลังบ้านบน Apps Script ใช้ Google Sheet เก็บข้อมูล) และ `index.html` (หน้าเว็บบน GitHub Pages) ทุกส่วนใช้ได้ฟรี

ขั้นตอนที่ 1–3 ทำครั้งเดียวตอนติดตั้ง หลังจากนั้นจัดการทุกอย่างจากหน้าเว็บ ไม่ต้องเปิดชีต

## 1. Apps Script (ครั้งเดียว)

1. สร้าง Google Sheet เปล่า แล้วไปที่ ส่วนขยาย → Apps Script
2. วางโค้ดจาก `Code.gs` ทับโค้ดเดิม แล้วใส่ `CLIENT_ID` ใน `CONFIG`
3. Project Settings (รูปเฟือง) → Time zone เลือก `(GMT+07:00) Bangkok`
4. เลือกฟังก์ชัน `setup` แล้วกด Run และอนุญาตสิทธิ์ ระบบจะสร้างแท็บเก็บข้อมูล ตั้งอีเมลของคุณเป็นผู้ดูแลระบบ และตั้งเวลาส่งแจ้งเตือนให้
5. Deploy → New deployment → Web app → Execute as: **Me**, Who has access: **Anyone** แล้วคัดลอก URL ที่ลงท้ายด้วย `/exec`

ถ้าภายหลังแก้ `Code.gs` ต้องไปที่ Manage deployments → แก้ไข → Version: New version ระบบจะปรับโครงสร้างชีตให้เองโดยไม่ต้องรัน `setup` ซ้ำ

## 2. Client ID สำหรับล็อกอิน

ใช้ Client ID ตัวเดียวกับระบบติดตามเอกสารได้ ถ้าหน้าเว็บอยู่ใต้บัญชี GitHub เดิม ถ้าใช้บัญชีอื่น ให้เพิ่ม `https://ชื่อผู้ใช้.github.io` ใน Google Cloud Console → Clients → Authorized JavaScript origins

## 3. GitHub Pages

ใส่ `API_URL` และ `CLIENT_ID` ใน `CONFIG` ของ `index.html` อัปโหลดขึ้น repo แล้วเปิด Settings → Pages

## 4. ตั้งค่าบนหน้าเว็บ (ปุ่มเฟือง มุมขวาบน เฉพาะผู้ดูแลระบบ)

**ผู้ใช้งาน** เพิ่มอีเมล Google ของทุกคนในฝ่าย ใส่ชื่อเล่น และเลือกบทบาท ถ้ามีคนย้ายออกให้ปิดการใช้งานแทนการลบ ชื่อในงานเก่าจะยังแสดงอยู่ ระบบไม่ให้ผู้ดูแลปิดสิทธิ์ของตัวเอง เพื่อกันไม่ให้ไม่มีใครเข้าหน้าตั้งค่าได้

**ภาคเรียน** เพิ่มชื่อ (เช่น `1/2569`) วันเริ่ม และวันสิ้นสุด
- งานใหม่เข้าภาคเรียนตามวันที่สร้าง งานที่สร้างช่วงปิดภาคเรียนเข้าภาคเรียนถัดไป และแก้ภาคเรียนของงานได้ในหน้ารายละเอียดงาน
- งานที่ยังไม่ปิดแสดงต่อในทุกภาคเรียน พร้อมป้าย "ยกมาจาก" จนกว่าจะปิดงาน
- งานที่ปิดแล้วดูย้อนหลังได้จากตัวเลือกภาคเรียนในหน้าหลัก
- เพิ่มภาคเรียนครั้งแรกเมื่อไร งานเดิมที่ยังไม่มีภาคเรียนจะถูกจัดเข้าให้อัตโนมัติ

**วันหยุด** ใส่วันหยุดราชการหรือวันที่วิทยาลัยหยุด ระบบไม่ส่งแจ้งเตือนรายวันในวันเหล่านี้ (เสาร์–อาทิตย์ข้ามให้อยู่แล้ว)

**แจ้งเตือน** ตั้งเวลาส่ง ลิงก์หน้าเว็บ รหัสเชื่อมต่อ LINE เลือกกลุ่ม ดูยอดโควตา และดูตัวอย่างข้อความ

## 5. LINE Official Account (แพ็กเกจฟรี)

1. สร้างบัญชีที่ LINE Official Account Manager เลือกแพ็กเกจฟรี (ไม่ต้องผูกบัตร)
2. ในหน้าตั้งค่าของบัญชี เปิดใช้ **Messaging API**
3. ไปที่ LINE Developers Console → channel ของบัญชีนี้ → แท็บ Messaging API
   - Issue **Channel access token (long-lived)** แล้วนำไปวางในหน้าเว็บ หมวดแจ้งเตือน
   - Webhook URL ใส่ URL `/exec` ของ Apps Script และเปิด Use webhook
   - เปิด **Allow bot to join group chats**
4. ใน LINE Official Account Manager ปิดข้อความตอบกลับอัตโนมัติและข้อความทักทาย
5. เชิญบอทเข้ากลุ่ม LINE ของฝ่าย แล้วกลับมาที่หน้าเว็บ หมวดแจ้งเตือน ตรวจชื่อกลุ่ม แล้วกด **ใช้กลุ่มนี้**
6. หลังตั้งกลุ่มแล้ว ควรกลับไปปิด Allow bot to join group chats (ถ้ามีคนเชิญบอทเข้ากลุ่มอื่น ระบบจะออกจากกลุ่มนั้นเองอยู่แล้ว)

ปุ่ม Verify ของ webhook ใน LINE Developers อาจแจ้งว่าไม่สำเร็จ เพราะ Apps Script ตอบกลับแบบ redirect ให้ทดสอบจริงด้วยการพิมพ์ `/วิธีใช้` ในกลุ่มแทน

## การแจ้งเตือน

| ข้อความ | เวลา (ค่าเริ่มต้น) | เงื่อนไข |
|---|---|---|
| รายวัน | วันทำการ 07:00 | ส่งเฉพาะวันที่มีงานเลยกำหนด ครบกำหนดวันนี้ หรือจะครบภายใน 3 วัน |
| สรุปรายสัปดาห์ | วันศุกร์ 15:00 | งานที่ปิดในสัปดาห์ งานเพิ่มใหม่ และงานค้างของแต่ละคน |

คำสั่งในกลุ่ม LINE ใช้แบบตอบกลับซึ่งไม่กินโควตา ได้แก่ `/งาน` `/งาน ชื่อเล่น` และ `/วิธีใช้`

กลุ่ม 5 คนใช้โควตาราว 130–150 ข้อความต่อเดือน จากโควตาฟรี 300 ข้อความ ถ้าโควตาหมด แพ็กเกจฟรีจะหยุดส่งจนถึงรอบเดือนใหม่ ไม่มีการเรียกเก็บเงิน

## สิทธิ์การใช้งาน

- ทุกคนเพิ่ม แก้ไข ลบ เปลี่ยนสถานะ และเปลี่ยนกำหนดส่งของงานใดก็ได้ ไม่ต้องใส่เหตุผล
- ระบบยังบันทึกประวัติไว้ในไทม์ไลน์ของงานว่าใครเปลี่ยนอะไรเมื่อไร
- การลบงานมีหน้าต่างยืนยันก่อน เพราะลบแล้วกู้คืนไม่ได้
- หน้าตั้งค่าระบบ (ผู้ใช้งาน ภาคเรียน วันหยุด และแจ้งเตือน) ใช้ได้เฉพาะผู้ดูแลระบบ

## ข้อจำกัดที่ควรรู้

- Apps Script อ่าน header ของคำขอไม่ได้ จึงตรวจลายเซ็นของ webhook LINE ไม่ได้ ระบบชดเชยด้วยการตอบเฉพาะกลุ่มที่ตั้งไว้ และให้ผู้ดูแลยืนยันกลุ่มเองจากหน้าเว็บ
- Apps Script ตอบช้ากว่าฐานข้อมูลจริง ประมาณ 1–3 วินาทีต่อคำขอ เพียงพอสำหรับทีม 5 คน
- ชีตยังเปิดดูได้ตามปกติในฐานะที่เก็บข้อมูลสำรอง แต่ไม่ควรแก้ตรง ๆ เพราะระบบตรวจรูปแบบข้อมูลเฉพาะที่ส่งมาจากหน้าเว็บ
