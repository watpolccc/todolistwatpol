# งานของฝ่าย — สอนติดตั้งตั้งแต่ต้นจนใช้งานได้

กระดานติดตามงานแบบไวท์บอร์ดติดโพสต์อิท สำหรับทีมเล็กในหน่วยงาน งานแต่ละชิ้นเป็นโน้ตหนึ่งใบ ลากไปมาระหว่างช่องสถานะได้ และมีบอตแจ้งเตือนเข้ากลุ่ม LINE ทุกเช้า

คู่มือนี้เขียนสำหรับฝ่ายที่ได้รับไฟล์ชุดนี้ไปและต้องการตั้งระบบของตัวเอง ทำตามทีละตอนจากบนลงล่าง แต่ละตอนมีจุดตรวจบอกว่าควรเห็นอะไรก่อนไปต่อ

## ภาพรวม

ระบบมีสามส่วน แต่ละฝ่ายมีของตัวเองแยกกัน ข้อมูลไม่ปนกัน

| ส่วน | อยู่ที่ไหน | ทำหน้าที่ |
|---|---|---|
| ที่เก็บข้อมูลและหลังบ้าน | Google Sheet + Apps Script ในบัญชี Google ของฝ่าย | เก็บงาน ตรวจสิทธิ์ ส่ง LINE |
| หน้าเว็บ | GitHub Pages | กระดานที่ทุกคนเปิดใช้ |
| บอตแจ้งเตือน | LINE Official Account ของฝ่าย | ประกาศงานเข้ากลุ่ม |

ทุกส่วนใช้แพ็กเกจฟรีได้ ไม่ต้องเช่าเซิร์ฟเวอร์

### สิ่งที่ต้องเตรียม

- บัญชี Google หนึ่งบัญชีสำหรับเป็นเจ้าของข้อมูล (แนะนำบัญชีกลางของฝ่าย ไม่ใช่บัญชีส่วนตัว เพราะถ้าเจ้าของย้ายออก ระบบต้องย้ายตาม)
- บัญชี GitHub
- บัญชี LINE ถ้าต้องการแจ้งเตือน (ข้ามตอนที่ 6 ได้ถ้าไม่ใช้)
- อีเมล Google ของทุกคนในฝ่ายที่จะเข้าใช้

### ไฟล์ที่ได้รับ

| ไฟล์ | นำไปไว้ที่ไหน |
|---|---|
| `Code.gs` | วางใน Apps Script (ตอนที่ 1) |
| `index.html`, `styles.css`, `app.js` | อัปโหลดขึ้น GitHub (ตอนที่ 3) |
| `icon.svg`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png`, `manifest.webmanifest` | อัปโหลดขึ้น GitHub พร้อมกัน |

> **ก่อนเริ่ม** ไฟล์ที่ได้รับมาอาจมีค่าของฝ่ายต้นทางติดมา คือ `CLIENT_ID` ใน `Code.gs` และ `API_URL` กับ `CLIENT_ID` ใน `app.js` ต้องเปลี่ยนเป็นของฝ่ายคุณเองตามตอนที่ 1–3 ถ้าไม่เปลี่ยน หน้าเว็บจะไปเรียกระบบของฝ่ายต้นทางและเข้าไม่ได้

## ตอนที่ 1: สร้างที่เก็บข้อมูลและหลังบ้าน

1. เปิด Google Sheets ด้วยบัญชีของฝ่าย สร้างชีตเปล่า ตั้งชื่อ เช่น "งานของฝ่าย (ข้อมูล)"
2. ไปที่เมนู ส่วนขยาย → Apps Script
3. ลบโค้ดตัวอย่างออก แล้ววางเนื้อหาทั้งหมดของ `Code.gs` ลงไป กดบันทึก
4. กดรูปเฟืองด้านซ้าย (Project Settings) → Time zone เลือก `(GMT+07:00) Bangkok`
5. กลับมาหน้าโค้ด เลือกฟังก์ชัน `setup` ที่แถบด้านบน แล้วกด Run
6. Google จะขอสิทธิ์ ให้กดอนุญาต ถ้าขึ้นหน้าเตือนว่าแอปยังไม่ได้ยืนยัน ให้กด Advanced แล้วเลือกไปต่อ (เป็นโค้ดของคุณเอง)
7. กด Deploy → New deployment → เลือกชนิด **Web app** ตั้ง Execute as: **Me** และ Who has access: **Anyone** แล้วกด Deploy
8. คัดลอก URL ที่ลงท้ายด้วย `/exec` เก็บไว้ จะใช้ในตอนที่ 3 และตอนที่ 6

**จุดตรวจ**
- ในชีตมีแท็บใหม่ 6 แท็บ: งาน, บันทึก, ผู้ใช้งาน, ภาคเรียน, ตั้งค่า, วันหยุด
- แท็บผู้ใช้งานมีอีเมลของคุณหนึ่งแถว บทบาทเป็น admin
- เปิด URL `/exec` ในเบราว์เซอร์แล้วเห็นข้อความ `{"ok":true,"service":"team-tasks"}`

## ตอนที่ 2: สร้าง Client ID สำหรับเข้าสู่ระบบด้วย Google

ระบบใช้บัญชี Google ยืนยันตัวตน จึงต้องมี Client ID ของตัวเอง ชื่อเมนูใน Google Cloud Console เปลี่ยนเป็นระยะ ถ้าหาไม่เจอให้ค้นคำว่า OAuth ในช่องค้นหาของ Console

ก่อนเริ่มต้องรู้ที่อยู่หน้าเว็บที่จะได้ในตอนที่ 3 ซึ่งมีรูปแบบ `https://ชื่อผู้ใช้GitHub.github.io/ชื่อ-repo/` ให้ตัดสินใจชื่อ repo ไว้ก่อน เช่น `tasks`

1. เปิด [Google Cloud Console](https://console.cloud.google.com/) ด้วยบัญชีของฝ่าย สร้างโปรเจกต์ใหม่
2. ไปที่ APIs & Services → OAuth consent screen ตั้งชนิดผู้ใช้เป็น External ใส่ชื่อแอปและอีเมลติดต่อ แล้วบันทึก
3. ในหน้าเดียวกัน ถ้าสถานะเป็น **Testing** จะเข้าได้เฉพาะอีเมลที่เพิ่มเป็นผู้ทดสอบ ให้กด **Publish app** เพื่อให้ทุกคนในฝ่ายเข้าได้ (ระบบขอแค่อีเมล จึงไม่ต้องผ่านการตรวจสอบของ Google)
4. ไปที่ Credentials → Create credentials → OAuth client ID → ชนิด **Web application**
5. กรอกสองช่องนี้ให้ถูกช่อง

| ช่อง | ใส่อะไร | ตัวอย่าง |
|---|---|---|
| Authorized JavaScript origins | โดเมนอย่างเดียว ไม่มีโฟลเดอร์ต่อท้าย ไม่มี `/` ปิดท้าย | `https://ชื่อผู้ใช้.github.io` |
| Authorized redirect URIs | ที่อยู่หน้าเว็บเต็ม และต้องมี `/` ปิดท้าย | `https://ชื่อผู้ใช้.github.io/tasks/` |

6. กด Create แล้วคัดลอก **Client ID** (ลงท้ายด้วย `.apps.googleusercontent.com`) ไม่ต้องใช้ Client secret
7. กลับไปที่ Apps Script เปิด `Code.gs` ใส่ Client ID ที่บรรทัด `CLIENT_ID:` ใน `CONFIG` ด้านบนสุด กดบันทึก
8. กด Deploy → Manage deployments → รูปดินสอ → Version: **New version** → Deploy (ต้องทำทุกครั้งที่แก้ `Code.gs` ไม่อย่างนั้นของเก่ายังทำงานอยู่)

**จุดตรวจ**
- มี Client ID เก็บไว้แล้ว และใส่ใน `Code.gs` พร้อม deploy รุ่นใหม่แล้ว
- ช่อง redirect URIs ไม่มีข้อความแดง ถ้ามีข้อความ `Invalid Origin: URIs must not contain a path` แปลว่าใส่ที่อยู่เต็มในช่อง origins ผิดช่อง

## ตอนที่ 3: นำหน้าเว็บขึ้น GitHub Pages

1. เปิดไฟล์ `app.js` ด้วยโปรแกรมแก้ข้อความ ด้านบนสุดมี `CONFIG` ให้ใส่สองค่า แล้วบันทึก
   - `API_URL`: URL `/exec` จากตอนที่ 1
   - `CLIENT_ID`: Client ID จากตอนที่ 2
2. ที่ GitHub สร้าง repository ใหม่ ตั้งชื่อตามที่ใช้ในตอนที่ 2 (เช่น `tasks`) เลือกเป็น Public
3. กด Add file → Upload files แล้วลากไฟล์ของหน้าเว็บทั้งหมดขึ้นไป (ทุกไฟล์ยกเว้น `Code.gs`) กด Commit
4. ไปที่ Settings → Pages ที่ Source เลือก Deploy from a branch เลือก branch `main` โฟลเดอร์ `/ (root)` แล้วกด Save
5. รอ 1–2 นาที หน้า Pages จะแสดงที่อยู่เว็บ

**จุดตรวจ**
- เปิดที่อยู่เว็บแล้วเห็นหน้าเข้าสู่ระบบที่มีไอคอนโพสต์อิทและปุ่ม Google
- ที่อยู่เว็บตรงกับที่ใส่ใน redirect URIs ทุกตัวอักษร

## ตอนที่ 4: เข้าสู่ระบบครั้งแรกและเพิ่มสมาชิก

1. เปิดหน้าเว็บบนคอมพิวเตอร์ กดปุ่ม Google แล้วเลือกบัญชีเดียวกับที่ใช้รัน `setup`
2. ควรเห็นกระดานเปล่าสี่ช่อง และมีรูปเฟืองที่มุมขวาบน
3. กดเฟือง → แท็บ **ผู้ใช้งาน** แก้ชื่อเล่นของตัวเอง (ถ้าไม่ใส่ ระบบจะใช้ส่วนหน้าของอีเมล)
4. เพิ่มสมาชิกทีละคน: อีเมล Google ชื่อเล่น และบทบาท ควรมีผู้ดูแลระบบอย่างน้อยสองคน
5. แท็บ **ภาคเรียน** เพิ่มภาคเรียนปัจจุบัน เช่น `1/2569` พร้อมวันเริ่มและวันสิ้นสุด (หน่วยงานที่ไม่ใช่สถานศึกษาใช้เป็นไตรมาสหรือปีงบประมาณได้ ดูหัวข้อ "ปรับให้เข้ากับฝ่ายของคุณ")
6. แท็บ **วันหยุด** กด "ดึงวันหยุดตอนนี้" เพื่อดึงวันหยุดราชการจากปฏิทิน Google

**จุดตรวจ**
- ให้สมาชิกหนึ่งคนลองเข้าจากเครื่องของเขา ควรเห็นกระดานเดียวกัน แต่ไม่มีรูปเฟือง
- ถ้าขึ้น "อีเมล … ยังไม่มีสิทธิ์ใช้ระบบ" แปลว่าล็อกอินผ่านแล้ว แต่อีเมลนั้นยังไม่ได้เพิ่ม หรือสะกดไม่ตรง

## ตอนที่ 5: ลองใช้กระดาน

ลองทำตามนี้หนึ่งรอบเพื่อให้รู้จักทุกส่วน

1. กด **เพิ่มงาน** ใส่ชื่องาน เลือกผู้รับผิดชอบ ใส่ช่วงวันทำงาน (เริ่ม ถึง กำหนดส่ง) และแท็กหนึ่งคำ เช่น `ประชุม` แล้วกดเพิ่ม โน้ตจะขึ้นในช่องรอดำเนินการทันที
2. **ลากโน้ต** ไปวางในช่องดำเนินการ บนโทรศัพท์ให้แตะค้างไว้ครู่หนึ่งแล้วลาก
3. กด **ตั้งสีแท็ก** ท้ายแถบแท็กสี เลือกสีให้แท็ก `ประชุม` โน้ตจะเปลี่ยนสีตาม
4. กดที่โน้ตเพื่อเปิดรายละเอียด พิมพ์ข้อความในช่อง **เพิ่มบันทึก** แล้วกดเพิ่ม จะขึ้นในไทม์ไลน์
5. กด **วงกลมมุมขวาบนของโน้ต** เพื่อปิดงาน โน้ตจะย้ายไปช่องเสร็จสิ้น กด "เลิกทำ" ในแถบด้านล่างได้ถ้ากดผิด
6. กดลูกศรที่หัวช่องเสร็จสิ้นหรือยกเลิกเพื่อ **พับช่อง** เป็นแถบแคบ

รายละเอียดอื่นของกระดาน

- สลับ "งานของฉัน / งานทั้งฝ่าย" ที่แถบบน กดแถบแท็กสีเพื่อกรองตามแท็ก
- งานวันเดียวใส่เฉพาะกำหนดส่ง โน้ตที่มีช่วงวันจะมีแถบบอกว่าผ่านช่วงมาแล้วเท่าไร
- โน้ตใช้สีของแท็กแรก งานไม่มีแท็กเป็นสีเหลือง
- งานทำซ้ำ (ทุกสัปดาห์หรือทุกเดือน) เมื่อปิดแล้วระบบสร้างรอบถัดไปให้เอง
- ช่องเสร็จสิ้นและยกเลิกแสดง 24 ใบล่าสุด งานเก่ากว่านั้นหาได้จากช่องค้นหา
- ทุกการแก้ไขเปลี่ยนบนหน้าจอทันทีแล้วบันทึกเบื้องหลัง ระหว่างนั้นใต้ชื่อระบบขึ้น "กำลังบันทึก…" ถ้าบันทึกไม่สำเร็จ หน้าจอจะเปลี่ยนกลับและแจ้งเหตุผล

## ตอนที่ 6: ตั้งบอตแจ้งเตือน LINE (ไม่บังคับ)

1. สร้างบัญชีที่ LINE Official Account Manager เลือกแพ็กเกจฟรี (ไม่ต้องผูกบัตร)
2. ในหน้าตั้งค่าของบัญชี เปิดใช้ **Messaging API**
3. ไปที่ LINE Developers Console → channel ของบัญชีนี้ → แท็บ Messaging API
   - กด Issue ที่ **Channel access token (long-lived)** แล้วคัดลอกไว้
   - ช่อง Webhook URL ใส่ URL `/exec` จากตอนที่ 1 และเปิด Use webhook
   - เปิด **Allow bot to join group chats**
4. ใน LINE Official Account Manager ปิดข้อความตอบกลับอัตโนมัติและข้อความทักทาย
5. ที่หน้าเว็บ กดเฟือง → แท็บ **แจ้งเตือน** วาง token ในช่องรหัสเชื่อมต่อ LINE แล้วกดบันทึกรหัส
6. เชิญบอตเข้ากลุ่ม LINE ของฝ่าย กลับมาที่แท็บแจ้งเตือน ตรวจชื่อกลุ่มที่ขึ้น แล้วกด **ใช้กลุ่มนี้**
7. ในแท็บเดียวกัน กด "ใช้ลิงก์ของหน้านี้" เพื่อแนบลิงก์เว็บท้ายข้อความ ตั้งเวลาส่ง แล้วกดบันทึกเวลาส่ง
8. กลับไปปิด Allow bot to join group chats ใน LINE Developers (ถ้ามีคนเชิญบอตเข้ากลุ่มอื่น ระบบจะออกจากกลุ่มนั้นเองอยู่แล้ว)

**จุดตรวจ**
- พิมพ์ `/วิธีใช้` ในกลุ่ม บอตควรตอบรายการคำสั่ง
- ในแท็บแจ้งเตือน กด "ข้อความรายวัน" ใต้หัวข้อดูตัวอย่าง ควรเห็นข้อความที่จะส่ง (ดูตัวอย่างไม่ใช้โควตา)
- ปุ่ม Verify ของ webhook ใน LINE Developers อาจแจ้งว่าไม่สำเร็จ เพราะ Apps Script ตอบกลับแบบ redirect ไม่ต้องสนใจ ให้ยึดผลจากการพิมพ์ `/วิธีใช้`

| ข้อความ | เวลา (ค่าเริ่มต้น) | เนื้อหา |

| รายวัน | วันทำการ 07:00 | เลยกำหนด / ครบกำหนดวันนี้ / ใกล้ครบกำหนด (ภายใน 3 วัน) / งานที่ตรงกับวันหยุด ถ้าไม่มีงานเข้าหัวข้อใดเลยจะไม่ส่ง |

- วันหยุดราชการดึงจากปฏิทิน Google ให้เองทุกวันที่ 1 ของเดือน วันที่หน่วยงานหยุดเพิ่มให้ใส่เองในแท็บวันหยุด
- คำสั่งในกลุ่ม: `/งาน` (งานค้างแยกตามคน) `/งาน ชื่อเล่น` และ `/วิธีใช้` เป็นการตอบกลับ ไม่กินโควตา
- กลุ่ม 5 คนใช้โควตาราว 130–150 ข้อความต่อเดือน จากโควตาฟรี 300 ข้อความ ถ้าโควตาหมด แพ็กเกจฟรีจะหยุดส่งจนถึงรอบเดือนใหม่ ไม่มีการเรียกเก็บเงิน

## ตอนที่ 7: ใช้บนโทรศัพท์

- เปิดที่อยู่เว็บใน Safari หรือ Chrome กด "เข้าสู่ระบบด้วย Google" ระบบจะพาไปหน้า Google แล้วกลับมาเอง
- เบราว์เซอร์ที่ฝังในแอป LINE, Facebook หรือ Instagram ล็อกอิน Google ไม่ได้ ลิงก์ท้ายข้อความของบอตมี `?openExternalBrowser=1` ต่อท้ายให้แล้วเพื่อให้ LINE เปิดในเบราว์เซอร์ของเครื่อง ถ้าส่งลิงก์เข้ากลุ่มเอง ให้ต่อท้ายแบบเดียวกัน
- เพิ่มไปหน้าจอหลักได้จากเมนูแชร์ของเบราว์เซอร์ จะได้ไอคอนโพสต์อิทและเปิดแบบเต็มจอ

## อัปเดตระบบ

- **แก้ `Code.gs`:** วางทับใน Apps Script แล้ว Deploy → Manage deployments → แก้ไข → Version: **New version** ที่อยู่ `/exec` คงเดิม ระบบปรับโครงสร้างชีตให้เอง ไม่ต้องรัน `setup` ซ้ำ
- **แก้ `styles.css` หรือ `app.js`:** เปิด `index.html` เพิ่มเลขท้าย `styles.css?v=…` และ `app.js?v=…` ขึ้นหนึ่งทุกครั้ง แล้วอัปโหลดทั้งไฟล์ที่แก้และ `index.html`
- เมื่อรับไฟล์รุ่นใหม่จากฝ่ายต้นทาง อย่าลืมใส่ `API_URL` และ `CLIENT_ID` ของฝ่ายคุณกลับเข้าไปใน `app.js` และ `Code.gs`

## สิทธิ์การใช้งาน

- ทุกคนเพิ่ม แก้ไข ลบ เปลี่ยนสถานะ เปลี่ยนวันทำงานของงานใดก็ได้ และตั้งสีแท็กได้
- ระบบบันทึกประวัติไว้ในไทม์ไลน์ของงานว่าใครเปลี่ยนสถานะ กำหนดส่ง หรือผู้รับผิดชอบเมื่อไร
- การลบงานมีหน้าต่างยืนยันก่อน เพราะลบแล้วกู้คืนไม่ได้
- หน้าตั้งค่าระบบใช้ได้เฉพาะผู้ดูแลระบบ และผู้ดูแลปิดสิทธิ์ของตัวเองไม่ได้
- คนที่ย้ายออกให้ปิดการใช้งานแทนการลบ ชื่อในงานเก่าจะยังแสดงอยู่

## ข้อจำกัดที่ควรรู้ก่อนตัดสินใจใช้

- **ความเร็ว:** Apps Script ใช้เวลาราว 1–3 วินาทีต่อคำขอ ระบบชดเชยด้วยการแสดงข้อมูลล่าสุดที่เก็บไว้ในเครื่องทันทีและบันทึกทุกอย่างเบื้องหลัง สิ่งที่ยังต้องรอคือการเปิดครั้งแรกบนเครื่องใหม่ และการเห็นงานที่คนอื่นเพิ่งแก้
- **ขนาดทีม:** ออกแบบสำหรับทีมเล็ก ระบบนี้ใช้จริงกับทีมราว 5 คน ยังไม่ได้ทดสอบกับทีมใหญ่หรือข้อมูลหลายพันงาน
- **ปิดแท็บระหว่างบันทึก:** ถ้าปิดขณะขึ้น "กำลังบันทึก…" เบราว์เซอร์จะถามก่อน ถ้ายืนยันปิด การแก้ไขล่าสุดอาจไม่ถูกบันทึก
- **แก้ชีตโดยตรง:** เปิดดูได้ แต่ไม่ควรแก้ เพราะระบบตรวจรูปแบบข้อมูลเฉพาะที่ส่งมาจากหน้าเว็บ
- **ข้อมูลในเครื่อง:** หน้าเว็บเก็บรายการงานล่าสุดไว้ในเบราว์เซอร์เพื่อเปิดได้เร็ว ออกจากระบบแล้วข้อมูลนี้ถูกลบ บนเครื่องที่ใช้ร่วมกันควรออกจากระบบทุกครั้ง
- **ความเป็นส่วนตัวของโค้ด:** repo บน GitHub Pages แบบฟรีต้องเป็น Public ใครก็เห็นโค้ดหน้าเว็บและที่อยู่ `/exec` ได้ แต่เข้าถึงข้อมูลไม่ได้ถ้าอีเมลไม่อยู่ในรายชื่อผู้ใช้งาน
- **webhook ของ LINE:** Apps Script อ่าน header ของคำขอไม่ได้ จึงตรวจลายเซ็นของ webhook ไม่ได้ ระบบชดเชยด้วยการตอบเฉพาะกลุ่มที่ตั้งไว้ และให้ผู้ดูแลยืนยันกลุ่มเองจากหน้าเว็บ
- **หน้าตา:** กระดานเป็นสีขาวเสมอ ไม่สลับตามโหมดมืดของเครื่อง
